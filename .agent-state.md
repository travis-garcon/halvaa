# Halvaa Agent State

This file is the live project memory. Read it before substantive work and
append a new Work Phase for every new user request.

## Project Summary

Halvaa is a multilingual digital memorial platform with a Next.js frontend,
FastAPI backend, PostgreSQL persistence, media storage, Mapbox-based discovery,
OTP authentication, and localized memorial creation and display.

## Architecture

- Frontend: Next.js App Router, React, TypeScript, next-intl, Swiper, Tailwind/CSS.
- Backend: FastAPI, SQLAlchemy, Alembic, PostgreSQL, media processing/storage.
- Runtime: Docker Compose services for frontend, backend, database, Redis, maps,
  and Zitadel-related infrastructure. On this low-memory host, production
  frontend deployment compiles Next.js on the host and packages its standalone
  output with `frontend/Dockerfile.runtime`.
- Availability control: Nginx guards only Halvaa-owned frontend, API, and
  identity routes with `/etc/nginx/halvaa-maintenance.enabled`. Dedicated
  shared-project routes bypass the guard. `/usr/local/sbin/halvaa-site down`
  enables the guard and stops only Halvaa's three public containers; `up`
  starts them, waits for frontend/backend readiness, and then removes the
  guard. No rebuild or Nginx reload is required for either toggle.
- Localization: English, Persian, Arabic, and Chinese message catalogs.
- Store: synchronized catalog with idempotent payment fulfillment. Store
  checkout requires all five profile fields (name, email, phone, locale, and
  address) before a purchase record can be created.
- Memorial status: persisted public view counts drive popularity, and one
  shared badge precedence is admin-featured gold, purchased-verification blue,
  then 1,000-view popularity gray.

than understand storage taxonomy.

or browser storage loss.
